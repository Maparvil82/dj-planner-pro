## Corrección tras el primer intento

El build 27 falló porque el perfil de aprovisionamiento no incluye APNs y `expo-notifications` lo solicitaba por defecto. Se configura `enableRemoteNotifications=false`, opción oficial de Expo para apps con notificaciones locales, y se verifica mediante introspección que no se genera `aps-environment`. La app no registra tokens push remotos; los recordatorios existentes son locales y se conservan. Las seis pruebas específicas de notificaciones y revisión posterior pasan.

Se declara además `expo-asset@58.0.18` como dependencia directa requerida por `expo-audio`; ya estaba instalada como dependencia transitiva. Se mantiene el resto de versiones y no se generan credenciales Apple nuevas. Se ha solicitado otro build con la misma versión 1.0.5 y numeración automática.

## Corrección de RevenueCat tras el build 28

El segundo intento superó la firma, pero RevenueCat iOS 5.61.0, incluido en react-native-purchases 9.12.0, no compila con Xcode 27.1 por una declaración duplicada de `init(stringRepresentation:)` en `PaywallColor.swift`. RevenueCat documenta la corrección desde iOS SDK 5.78.0. Se actualiza solo la biblioteca de compras a `react-native-purchases@10.16.0`, que utiliza iOS SDK 5.99.0 y Hybrid Common 19.17.0; no se cambian productos, precios, cuentas ni permisos del servidor.
